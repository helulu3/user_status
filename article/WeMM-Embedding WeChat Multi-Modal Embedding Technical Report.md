## 一、概述

WeMM-Embedding 是一个**通用多模态 Embedding 模型家族**（2B / 4B / 9B 三个规格），将文本、图像、视频、视觉文档以及任意交错多模态输入编码到统一向量空间，服务于检索、推荐、分类、Agent 等场景。

核心亮点：

- **参数效率极高**: 2B 小模型即超过此前最强的 8B 开源基线（MMEB-v2）
- **SOTA**: 9B 在 MMEB-v2 官方榜单以 **80.6** 总分排名第一，超过所有开源与闭源商业模型
- **工业级验证**: 微信内部 26 任务 benchmark 大幅提升，14 个线上 A/B 实验一致正向，已规模部署于视频号、公众号、朋友圈、电商的推荐与搜索系统

## 二、模型设计

### 2.1 基础架构

- 基于**原生多模态的 Qwen3.5 backbone**，天然支持文本/图像/视频的任意交错输入
- **Last-token pooling**: 在输入序列末尾追加专用 `<embedding>` token，取其最后一层 hidden state 并做 L2 归一化作为输出表示
- 因果注意力下可在序列**不同位置插入多个 `<embedding>` token**——例如视频 token 后一个、ASR 转写文本后一个，单次前向即可同时获得"纯视频"与"视频+文本"两种表示，适配不同下游需求

### 2.2 Matryoshka 可变维度（MRL）

- 一次前向，按需截取前 d 维再归一化即可得到低维 embedding
- 支持维度：2B → 64~2048；4B → 64~2560；9B → 64~4096
- **256 维即可保留完整维度 98.7% 的图像/视频性能**，512 维达 99% 以上，适合存储/检索效率敏感场景
- 当前**不支持音频**输入

## 三、数据构造

### 3.1 统一 Pair 格式

所有异构任务统一表示为：

```
z = (I, q, c, N, y)
  I: 可选任务指令        q: 源实例（文本/图像/视频/交错）
  c: 配对目标           N: 可选显式难负例集    y: 可选分级相关度分数
```

分类任务的目标用类名或类别的自然语言描述表示；同 batch 内其他样本的目标充当 in-batch 负例，重复目标通过语义掩码排除假负例。

### 3.2 大规模数据（数亿对）

| 数据类型 | 说明 |
| --- | --- |
| 弱监督对 | 网络规模图文/视频-文本对，覆盖广但监督较粗 |
| Caption 对 | 显式描述视觉内容（实体、属性、关系、空间、动作、事件） |
| 检索对 | 单模态/跨模态/组合查询/推理/指令/长上下文/时空定位/Agent 检索 |
| 分类对 | 目标为类名或类别描述的源-标签对（物体、场景、动作识别） |
| 多模态 QA 对 | 感知、空间关系、OCR、知识、推理、文档/图表/事件理解 |
| 分级相关度对 | 人工离散相关度等级，支持排序导向训练（推荐场景） |

### 3.3 精选数据集（约为大规模集的 1/10）

- **Semantic-ID 引导重采样**: 用中间 checkpoint 编码每对数据中较长的一侧，训练三级 RQ-KMeans 量化器得到三段式语义 ID；按码本分配密度降采样高频语义模式，缓解分布倾斜
- **质量精炼**: 用 MLLM 判断源-目标是否满足预期匹配关系并过滤错配样本；修正弱监督文本的事实性错误（保持原有 alt-text 风格）
- **难负例构造**: 文本目标由 MLLM 生成"看似合理但错误"的候选；图像/视频目标用中间 checkpoint 从任务候选池检索相似样本；部分候选集再用 reranker 打分，提供细粒度监督

## 四、训练策略（两阶段）

### 4.1 Stage 1：大规模多模态对齐

在数亿对数据上建立通用表示空间：

- **InfoNCE 对比学习**：每个 batch 来自单一数据集（**任务一致性 batching**），保证候选空间一致、负例更有信息量；可学习温度 τ
- **Duplicate-aware masking**：源端相似度超阈值 → 屏蔽其全部关联候选；目标端与当前正例过近 → 从负例池剔除（含显式难负例）
- **分级相关性学习**：对带人工相关度等级的数据采用 **score-gap-weighted CoSENT** 排序目标，相关度差距越大的 pair 对权重越大，同标签不施加排序约束
- **MRL 联合优化**：对比/排序目标在每个支持维度上独立计算并加权求和

### 4.2 Stage 2：精选精调 + 蒸馏

- **Reranker 监督**：训练专门的多模态 reranker 对挖掘出的候选集打分，替换人工等级构造 query 内排序目标（score-gap CoSENT 形式）。经验上只在部分任务有稳定收益，因此**限定在可靠提升的任务子集使用**
- **Embedding 蒸馏（对小模型贡献最大）**：以冻结的同族 9B 模型为 teacher，对 batch 内 source→target 与 target→source **两个方向**的相似度分布做双向 KL 对齐。相比 one-hot 对比监督，teacher 分布保留了候选间的相对相似度结构，且无需额外离线标注，可跨异构 batch 通用
- **9B 的特殊处理**：没有更大 teacher，改为训练多个数据配方/配置互补的专业化 Stage-2 变体，再通过 **model merging** 合并得到最终 9B 模型
- **视觉输入预算扩大**：更高分辨率输入 + 更密的视频帧采样
- 总体目标：`L_Stage2 = L_Task + λ_Emb · L_Emb`

## 五、实验结果

### 5.1 MMEB-v2（78 个数据集，图像/视频/视觉文档）

| Model | Size | AVG | Image | Video | VisDoc |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3-VL-Embedding | 2B | 73.2 | 75.0 | 61.9 | 79.2 |
| DME-Small† | 2B | 74.8 | 75.9 | 65.6 | 79.9 |
| **WeMM-Embedding** | **2B** | **77.9** | **79.6** | **70.8** | **80.7** |
| **WeMM-Embedding** | **4B** | **79.2** | **80.8** | **72.1** | **82.0** |
| Qwen3-VL-Embedding | 8B | 77.8 | 80.1 | 67.1 | 82.4 |
| DME-Medium† | 9B | 78.4 | 79.8 | 70.8 | 82.0 |
| **WeMM-Embedding** | **9B** | **80.6** | **81.9** | **74.3** | **83.3** |

- 2B 版超 Qwen3-VL-Embedding-2B **4.7 分**、DME-2B 3.1 分，并略超 Qwen3-VL-Embedding-**8B**
- 9B 版 80.6 分，MMEB-v2 官方榜单第一（含 Seed-1.6-Embedding、DME-Large 等所有闭源/商业模型）

### 5.2 MMEB-v3（190 个任务，扩展文本/Agent/音频/MCMR）

| Model | Size | V3-All | Text | Agent | MCMR |
| --- | ---: | ---: | ---: | ---: | ---: |
| Qwen3-VL-Embedding | 2B | 50.9 | 39.2 | 39.3 | 42.0 |
| **WeMM-Embedding** | **2B** | **56.0** | **45.3** | **45.1** | **42.5** |
| **WeMM-Embedding** | **4B** | **58.2** | **47.9** | **49.0** | **41.9** |

- 全部规格均为榜单第一；Text 与 Agent 任务组也是最高分
- 注：11 个音频任务因不支持音频记 0 分

### 5.3 跨模态检索（12 个公开基准）

- 2B 得 **79.8**，超全部开源基线，与顶级闭源商业模型相当（Gemini Embedding 2 为 79.5、Amazon Nova MME 70.2、Voyage Multimodal 3.5 71.8）
- 4B / 9B 进一步提升至 **80.8 / 81.7**

### 5.4 微信内部评测与线上部署

- **内部 benchmark**（26 个真实业务任务：分类、搜索、跨域内容匹配、文章相关性、视频相关性）：2B 得 **72.0**，大幅领先 Qwen3-VL-Embedding-2B 的 60.9
- **线上**：14 个 A/B 实验一致正向并已全量推全；部署于**视频号、公众号、朋友圈、电商**的推荐与搜索
- **业务用法**：融合文本+封面图+视频帧的互补信号，用于推荐链路的候选召回、排序特征、用户序列建模、跨域内容理解；由 embedding 衍生的 **Semantic ID** 作为紧凑离散特征用于索引与序列建模；对长尾与新发布内容提升尤为明显

## 六、消融分析

### 6.1 MRL 维度敏感性

- 图像/视频：256 维保留 98.7%，512 维保留 99.2% / 98.8%
- 视觉文档对降维更敏感（信息密度高、含密集文本）
- 任务类型：分类最不敏感 < QA < **检索最敏感**（64/128 维明显下降）；256 维后三类任务均保留 97% 以上

### 6.2 Stage-1 设计消融（2B 小规模）

| 配置 | AVG |
| --- | ---: |
| 完整配置 | 71.9 |
| 去掉 task-specific instructions | 71.1（-0.8） |
| 去掉任务一致性 batching | 68.5（**-3.4**，影响最大） |
| 去掉 duplicate-aware masking | 71.4（-0.5） |

### 6.3 Stage-2 策略累积分析（2B，MMEB-v2）

| 累积配置 | AVG |
| --- | ---: |
| Stage-1 checkpoint | 75.7 |
| + 精选数据 | 76.6（+0.9） |
| + reranker 监督 | 76.7（+0.1） |
| + embedding 蒸馏 | 77.6（**+0.9**，三分域全面提升） |
| + 扩大视觉输入预算（最终） | 77.9（+0.3，视频任务受益最明显） |

## 七、结论与展望

- 两阶段策略（大规模对齐 → 精选数据 + 细粒度监督 + 跨尺度知识迁移）建立了通用多模态 embedding 新的性能-效率前沿
- 未来方向：向**全模态**（omni-modal，含音频）扩展、 scaling 到更大规模、持续改进数据精选与细粒度相关性监督
